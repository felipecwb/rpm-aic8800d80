# AIC8800D80 akmods RPM for Bazzite

This project packages [`shenmintao/aic8800d80`](https://github.com/shenmintao/aic8800d80)
as a Fedora **akmod**, the rpm-ostree equivalent of an Arch Linux DKMS package.
It is intended to keep the AIC Wi-Fi/Bluetooth adapter available after Bazzite
kernel updates without manually rebuilding the driver with a keyboard.

## What gets installed

Two packages are built:

- `akmod-aic8800d80`: keeps the module source in `/usr/src/akmods` and builds a
  kernel-specific `kmod-aic8800d80-<kernel>` RPM whenever the kernel changes.
- `aic8800d80-kmod-common`: installs firmware, udev rules, and the
  `usb_modeswitch` configuration.

The akmod builds these modules:

- `aic8800_fdrv`
- `aic_load_fw`
- `aic_zlp_quirk`

Bluetooth transport itself remains handled by the kernel's standard `btusb`
module.

## Important prerequisites

- The specs currently use upstream's `main` branch commit
  `27af5add83088af64b013ec99db1ddf824112e6e`. Devices reporting
  `chip_mcu_id=1` require upstream's `legacy-mcu1` branch instead.
- **Secure Boot must currently be disabled.** Universal Blue does not publish
  the private key used to sign its official kernel modules, so a local akmod
  cannot sign with that key. `install.sh` refuses installation when Secure Boot
  is enabled rather than leaving Bluetooth unavailable after reboot.
- Keep the previous Bazzite deployment available in GRUB until the new one has
  been tested.

## One-time build and installation

Clone this repository and run the build on the Bazzite machine:

```bash
git clone https://github.com/felipecwb/rpm-aic8800d80.git
cd rpm-aic8800d80
./build.sh
./install.sh
sudo systemctl reboot
```

To update this packaging later, pull the latest changes and rebuild:

```bash
cd rpm-aic8800d80
git pull --ff-only
./build.sh
./install.sh
sudo systemctl reboot
```

`build.sh` uses a Fedora Podman container matching Bazzite's Fedora release, so
RPM build tools do not need to be installed on the host. `install.sh` removes
the old, kernel-specific `aic8800d80` RPM when present and then stages both
local replacement RPMs with `rpm-ostree`. Their runtime dependencies, including
`akmods`, the compiler toolchains, and matching kernel development files, are
resolved as part of the deployment. Do not reboot between those two chained
rpm-ostree operations if you perform them manually.

If automatic Fedora-version detection is unavailable, specify it explicitly:

```bash
FEDORA_VERSION="$(rpm -E '%fedora')" ./build.sh
```

Artifacts are written to `results/fedora-<version>/`.

## Verification after reboot

```bash
rpm -q akmod-aic8800d80 aic8800d80-kmod-common
uname -r
modinfo -F filename aic8800_fdrv
modinfo -F vermagic aic8800_fdrv
modinfo -F filename aic_load_fw
modinfo -F filename aic_zlp_quirk
lsmod | grep -E 'aic8800|aic_load_fw|aic_zlp_quirk|btusb'
bluetoothctl list
```

The beginning of `aic8800_fdrv`'s `vermagic` should match `uname -r`.

## What happens during a Bazzite update

When rpm-ostree stages a deployment containing a new kernel, the `%post`
script generated by `kmodtool` invokes `akmods-ostree-post`. It recompiles the
three modules against that deployment's matching kernel headers and installs
the generated kmod RPM into the deployment before reboot.

No manual reinstall should be needed for ordinary compatible kernel updates.
Akmods automates compilation; it cannot repair driver source that is
incompatible with a future kernel API. In that case, update the pinned upstream
commit in both specs, bump the RPM version/release, and run `build.sh` and
`install.sh` again.

## Troubleshooting

Show the current and pending deployments:

```bash
rpm-ostree status
```

Inspect akmods logs:

```bash
sudo find /var/cache/akmods/aic8800d80 -type f -name '*.log' -print
sudo journalctl -b -u akmods --no-pager
sudo journalctl -t 'rpm-ostree(akmod-aic8800d80.post)' --no-pager
```

Confirm matching headers exist:

```bash
test -d "/usr/src/kernels/$(uname -r)" && echo 'kernel headers present'
rpm -q "kernel-devel-$(uname -r)"
```

If the new deployment does not have working networking/Bluetooth, select the
previous Bazzite deployment in GRUB. From a working deployment, remove the
packages with:

```bash
sudo rpm-ostree uninstall akmod-aic8800d80 aic8800d80-kmod-common
sudo systemctl reboot
```

## Package maintenance

Both specs must always use the same values for:

- `commit`
- `commitdate`
- `Version`
- `Release`

The source is deliberately pinned to a full commit so a previously built RPM
always contains reproducible driver source rather than whatever happens to be
on an upstream branch later.
